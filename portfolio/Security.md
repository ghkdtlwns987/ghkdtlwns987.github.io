## 4. 프로젝트 및 업무 경험

### 4-1. Unreal Engine 퍼징 기반 취약점 분석

| 항목 | 내용 |
|---|---|
| 기간 | 교육 프로그램 참여: 2021.07~2022.03 / 프로젝트 실제 수행 기간: 【확인 필요】 |
| 목표 | Unreal Engine 파일 파서와 Pixel Streaming 기능의 공격면을 분석하고 실제 취약점을 발견·검증 |
| 형태·역할 | 교육 프로그램 내 프로젝트. 퍼징 환경 구축, 계측 적용, 코드 감사, PoC 작성에 참여. **개인이 담당한 취약점과 단계는 확인 후 분리 기재** |
| 사용 기술·도구 | C/C++, AFL++, Clang/LLVM, Unreal Engine, WinDbg/GDB, Linux |

**문제와 해결.** 대형 엔진의 기본 빌드 환경에 퍼징 도구를 그대로 적용하기 어려워 빌드 시스템을 수정하고 AFL++ 계측을 적용했습니다. 파일 파서와 Pixel Streaming의 입력 지점을 대상으로 퍼징과 코드 감사를 병행하고, 발견한 문제는 재현 가능한 PoC로 검증했습니다. 【당시 구체적인 계측 오류·크래시 분류 방식·해결 과정을 본인 기록으로 보강】

**성과와 기여.** 프로젝트 전체 결과로 RCE 2건과 DoS 1건을 발굴했고, 공개 이력에는 버그 바운티 보상이 기재돼 있습니다. 최종본에는 **각 취약점의 개인 기여, 보고·검증 여부, 공개 가능한 증빙**을 구분해 적겠습니다. 취약점 분석에서는 탐지 결과 자체보다 재현 조건, 영향 범위, 원인 코드의 확인이 중요하다는 점을 배웠습니다.

### 4-2. 침해사고 분석 및 대응 프로젝트

| 항목 | 내용 |
|---|---|
| 기간 | 2022.09 / 실제 분석·조치 기간: 【확인 필요】 |
| 목표 | 웹 서버와 Windows PC에 남은 증거를 연결해 침해 경로를 재구성하고 취약점을 조치 |
| 형태·역할 | 침해대응·분석 경진대회 팀 프로젝트. 웹 서버·PC 분석 및 대응 중 본인 담당 범위 【최종 확인 필요】 |
| 사용 기술·도구 | Apache·SSH 로그, Windows 이벤트·파일 아티팩트, PHP·SQL, Docker, iptables, Snort 3, ModSecurity 등 【본인 사용 범위 확인 필요】 |

**문제와 해결.** 공격 흔적이 서버 로그, PC 이벤트와 악성 실행파일에 나뉘어 있어 한 자료만으로는 전체 흐름을 설명하기 어려웠습니다. 웹셸 실행·리버스 셸·권한 상승·백도어·DB 조작 정황을 서버 증거로 연결하고, PC에서는 다운로드·실행·지속성·C2 연결 흔적을 시간순으로 대조했습니다. 확인된 웹 취약점에는 입력 처리와 업로드·접근 정책을 수정하고 방화벽·IPS·WAF를 구성했습니다. 전송의 **시도·정황**과 **성공이 확인된 사실**은 구분했습니다.

**성과와 기여.** 팀은 대회에서 우수상을 받았습니다. 분석 타임라인과 대응 방안을 산출물로 정리했습니다. 최종본에는 발표자료 중 직접 작성·검증한 부분, 수정 전후 재현 결과와 증빙을 추가합니다. 이 경험을 통해 여러 증거를 교차 확인하고, 불확실한 결론은 단정하지 않는 분석 태도를 익혔습니다.

### 4-3. 인과 지식그래프·LLM 에이전트 기반 취약점 탐지 연구: CLEAR

| 항목 | 내용 |
|---|---|
| 기간 | 【연구 시작·종료 기간 확인 필요】 |
| 목표 | 구조가 비슷한 취약 코드와 패치 코드를 구별하도록 취약점의 발생 조건과 수정 논리를 추론에 반영 |
| 형태·역할 | 공동연구, 공동 제1저자. **지식그래프 설계·구현·실험·논문 작성 중 개인 담당 범위 확인 필요** |
| 사용 기술·도구 | Python, LangChain, GPT-4o-mini, 임베딩 모델, 지식그래프, 취약·패치 코드 쌍 평가 |

**문제와 해결.** 기존 탐지 방법은 외형이 유사한 취약 코드와 패치 코드를 혼동할 수 있고, 외부 지식을 검색하더라도 현재 코드와 관련 없는 정보가 추론을 방해할 수 있습니다. 연구에서는 취약점 정보를 **진입 지점·사전 조건·근본 원인·수정 의도**로 구조화하고, 관련 지식을 검색·필터링한 뒤 역할별 에이전트가 가설 생성·반박·최종 판단을 수행하도록 설계했습니다.

**성과와 기여.** 연구는 IEEE/ACM ASE 2026에 채택됐습니다. 공개 연구 페이지에는 PrimeVul에서 Pair-Correct(P-C) 19.17%, 비교 방법 대비 130.7% **상대 개선**이 기재돼 있습니다. 최종본에는 데이터셋·비교 기준·평가 조건을 함께 표시하고 공동연구의 개인 기여를 분리합니다. 이 연구를 통해 탐지 성능뿐 아니라 **패치 후 달라진 조건을 올바르게 판단하는지** 검증해야 함을 확인했습니다.

| 항목 | 내용 |
|---|---|

| 목표 | 학생들이 보안 인프라 설정을 암기하는 데서 벗어나 상황에 맞게 원리를 적용하도록 교육 |
| 역할 | 정보보안 강사. 실습 환경 구성, 강의 자료 제작, 실습·문제풀이 지도 |
| 사용 기술·도구 | VMware, Linux, Apache, 방화벽, 웹 보안 실습 도구 등 【실제 사용한 도구별 범위 확인 필요】 |

**문제와 해결.** 풀이 과정을 기록한 자료를 제공했지만, 기초 지식이 부족한 학생들은 설정의 이유보다 순서를 외웠습니다. 관련 경험이 적은 사람에게 강의를 시연해 이해하기 어려운 부분을 확인하고, 설명과 자료를 수정했습니다. 학생들의 반응을 살피며 실습 문제와 설명 방식을 조정했습니다.

**성과와 기여.** 지도한 학생들이 지방 기능경기대회에서 금·은·동·장려상, 전국대회에서 은상과 장려상을 받았습니다. 이는 **학생들의 수상 성과**이며, 본인의 기여는 실습 환경·강의 자료·지도 과정으로 구분합니다. 기술적 내용을 재현 가능한 절차로 문서화하고 상대의 이해 수준에 맞게 설명하는 경험을 쌓았습니다.

## 5. 기타 활동

- **후속 취약점 탐지 연구 CRAFT:** 취약점 유형별 인과 지식 표현과 전문가 추론을 연구한 1저자 원고. 현재 공개 이력에는 *IEEE TDSC 투고 상태*로 기재돼 있으므로, 제출 직전 상태와 공개 가능한 수치·그림을 재확인합니다.
- **취약·패치 코드 쌍 평가:** 동일 함수의 취약 버전과 패치 버전을 함께 평가해 탐지 방법의 실패 유형을 분석한 학위 연구. CLEAR·CRAFT의 평가 관점과 연결됩니다.
- **자격·수상:** 지원 직무와 직접 관련되는 항목만 사실 확인 후 기재합니다. 【필요시 추가】
