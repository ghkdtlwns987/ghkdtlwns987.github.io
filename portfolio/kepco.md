## 01. Research Motivation

**높은 AI 성능은 올바른 판단 능력을 의미하는가?**

최근 AI 모델은 자연어 처리뿐만 아니라 소프트웨어 분석, 이상 탐지, 취약점 탐지와 같이 복잡한 판단이 필요한 영역까지 빠르게 활용 범위를 넓히고 있습니다. 특히 코드와 자연어를 함께 학습한 모델의 발전으로 소프트웨어의 취약 여부를 자동으로 판단하는 연구에서도 높은 성능이 보고되고 있습니다.

그러나 높은 예측 성능이 곧 모델이 판단에 필요한 의미를 실제로 식별하고 있음을 의미하는지는 별도로 검증할 필요가 있습니다.

기존 AI 모델은 학습 데이터에서 관찰한 특징을 바탕으로 입력과 출력 사이의 관계를 학습합니다. 이 과정에서 실제 판단에 필요한 원인이나 의미뿐만 아니라 특정 클래스와 우연히 함께 나타나는 표면적인 특징까지 활용할 가능성이 있습니다.

이러한 모델이 기존 평가 데이터에서는 높은 정확도를 보이더라도, 판단에 중요한 의미는 달라지고 표면적인 특징은 거의 유지되는 입력이 주어졌을 때 올바르게 판단할 수 있는지는 명확하지 않습니다.

본 연구는 이러한 문제를 소프트웨어 취약점 탐지를 대상으로 실증적으로 분석했습니다.

## 02. Why Vulnerability Detection?

**취약 코드와 패치 코드는 비슷하지만 의미는 다릅니다**

소프트웨어 취약점 탐지는 AI 모델의 이러한 판단 능력을 분석하기에 적합한 문제입니다.

실제 소프트웨어 취약점은 프로그램 전체의 구조가 잘못되어 발생하기보다 특정 입력에 대한 검증 부족, 잘못된 상태 처리, 메모리 관리 오류, 권한 검증 누락과 같이 일부 코드의 조건이나 동작으로 인해 발생하는 경우가 많습니다.

취약점을 수정할 때도 전체 프로그램을 새롭게 작성하기보다 취약점의 원인이 되는 일부 코드를 변경하는 경우가 일반적입니다.

따라서 동일 함수의 취약 버전과 패치 버전은 대부분의 코드 구조와 기능을 공유하지만, 보안 관점에서는 명확히 다른 의미를 갖습니다.

1. **Vulnerable Code** - 취약점의 원인이 되는 조건 또는 동작이 존재
2. **Security Patch** - 취약점과 관련된 일부 코드 수정
3. **Patched Code** - 전체적인 구조는 유사하지만 취약점의 원인이 제거됨

이러한 두 코드를 정확하게 구별하기 위해서는 단순히 코드의 전체적인 형태가 유사한지를 판단하는 것만으로는 충분하지 않습니다. 모델이 취약점의 존재 여부를 결정하는 코드 변화에 올바르게 반응해야 합니다.

즉, Vulnerable–Patched Pair는 다음 질문을 분석할 수 있는 환경을 제공합니다.

> 모델은 코드가 비슷하기 때문에 같은 판단을 내리는가, 아니면 보안적으로 중요한 변화에 따라 판단을 바꾸는가?

## 03. Problem Definition

**기존 취약점 탐지 모델은 취약점과 관련된 미세한 코드 차이를 실제로 식별하고 있는가?**

기존 AI 기반 소프트웨어 취약점 탐지 모델은 높은 분류 성능을 보여왔지만, 이러한 성능이 모델이 실제 취약점의 원인이 되는 코드 차이를 식별한 결과인지는 별도로 확인할 필요가 있습니다.

기존 평가에서는 일반적으로 취약 코드와 정상 코드를 서로 독립적인 샘플로 구성하고 Accuracy, Precision, Recall, F1-score 등의 분류 지표를 통해 모델의 성능을 측정합니다.

이러한 평가는 모델이 각 샘플의 정답을 얼마나 정확하게 예측하는지는 보여주지만, 판단에 중요한 코드가 변경되었을 때 모델의 예측도 올바른 방향으로 변화하는지까지 직접적으로 보여주지는 않습니다.

예를 들어 동일 함수에 보안 패치가 적용되었음에도 모델이 패치 전후 코드에 모두 Vulnerable이라고 예측할 수 있습니다. 개별 샘플 관점에서는 취약 버전에 대한 예측이 정답이지만, Pair 관점에서는 보안 패치에 따른 의미 변화를 구별하지 못한 것입니다.

반대로 취약 코드를 Benign으로 판단하고 패치된 코드를 Vulnerable로 판단하는 경우도 존재할 수 있습니다. 이러한 예측은 단순한 오분류를 넘어 실제 보안과 관련된 코드 변화와 모델의 판단 방향이 일치하지 않는다는 것을 의미합니다.

본 연구에서는 이러한 문제의식을 바탕으로 기존 AI 기반 취약점 탐지 방법들을 직접 실험하고, 모델이 취약점과 관련된 미세한 코드 변화를 실제로 식별할 수 있는지를 Pairwise 관점에서 분석했습니다.

## 04. Research Question

**기존 AI 기반 취약점 탐지 모델은 표면적인 코드 패턴을 넘어, 취약 코드와 패치 코드 사이의 미세한 차이를 정확하게 구별할 수 있는가?**

이를 확인하기 위해 동일 함수의 취약 버전과 패치 버전을 함께 평가했습니다.

핵심은 단순히 두 샘플을 각각 맞혔는지를 확인하는 것이 아니라, 취약점과 관련된 코드 변화가 발생했을 때 모델의 판단 역시 올바른 방향으로 변화하는가를 분석하는 것입니다.

이를 통해 다음 세 가지 관점에서 기존 방법을 분석했습니다.

1. 모델은 Vulnerable–Patched Pair를 모두 정확하게 판단할 수 있는가?
2. 보안 패치가 적용되었을 때 모델의 판단은 올바른 방향으로 변화하는가?
3. 기존 개별 샘플 기반 평가와 Pairwise 평가 사이에는 어떠한 차이가 나타나는가?

## 05. Pairwise Evaluation

**Vulnerable–Patched Pair 기반 평가**

동일 함수의 취약 버전과 패치 버전을 하나의 Pair로 구성하여 기존 취약점 탐지 방법들을 평가했습니다.

취약 버전과 패치 버전은 대부분의 코드가 동일하기 때문에 두 버전을 모두 정확하게 판단하기 위해서는 모델이 취약점과 관련된 미세한 코드 차이에 올바르게 반응해야 합니다.

모델이 하나의 Pair에 대해 내린 두 번의 판단을 다음 네 가지 유형으로 구분했습니다.

| Type | Vulnerable Code | Patched Code | Description |
| --- | --- | --- | --- |
| **P-C (Correct)** | Vulnerable | Benign | 두 버전을 정확하게 구별 |
| **P-V (Vulnerable)** | Vulnerable | Vulnerable | 두 버전을 모두 취약으로 판단 |
| **P-B (Benign)** | Benign | Benign | 두 버전을 모두 정상으로 판단 |
| **P-R (Reversed)** | Benign | Vulnerable | 취약 여부를 반대로 판단 |

### P-C: Correct Prediction

취약 버전을 Vulnerable, 패치 버전을 Benign으로 판단한 경우입니다.

이는 모델의 판단이 보안 패치에 따른 코드 변화와 올바르게 일치한 경우로 볼 수 있습니다.

### P-V / P-B: Same Prediction

두 버전을 모두 Vulnerable 또는 모두 Benign으로 판단한 경우입니다.

코드에는 취약점을 제거하는 변화가 발생했지만 모델의 판단은 변화하지 않은 경우입니다. 이러한 예측 행동은 개별 샘플 기반 평가만으로는 충분히 드러나지 않을 수 있습니다.

### P-R: Reversed Prediction

취약 버전을 Benign으로, 패치 버전을 Vulnerable로 판단한 경우입니다.

이는 취약점과 관련된 코드 변화와 모델의 판단 방향이 완전히 반대로 나타난 경우이며, 모델의 예측 신뢰성을 분석하는 데 중요한 유형입니다.

## 06. Vulnerability Pairwise Score

**기존 분류 성능만으로 충분한가?**

일반적인 Accuracy나 F1-score는 개별 샘플에 대한 예측 성능을 측정합니다.

그러나 본 연구에서 관심을 가지는 것은 개별 샘플 하나의 정답 여부뿐만 아니라 동일한 함수에서 취약점과 관련된 코드가 변경되었을 때 모델이 두 버전을 올바르게 구별하는가입니다.

이를 분석하기 위해 Vulnerability Pairwise Score(VPS)를 활용했습니다.

VPS는 취약 코드와 패치 코드를 정확하게 구별한 **P-C(Correct)**와 판단이 완전히 역전된 **P-R(Reversed)**을 함께 고려합니다.

이를 통해 모델이 단순히 특정 클래스의 샘플을 많이 맞히는지를 넘어, 보안적으로 중요한 코드 변화에 얼마나 올바르게 반응하는지를 비교했습니다.

### Why Pairwise?

**기존 평가**

단일 코드를 모델에 입력하고 Vulnerable / Benign으로 분류합니다.

- 입력: Code
- 과정: Code -> Model -> Vulnerable / Benign

**Pairwise 평가**

취약 코드와 패치 코드를 함께 모델에 입력하고, 두 판단의 관계를 분석합니다.

- 입력: Vulnerable Code, Patched Code
- 과정: (Vulnerable Code, Patched Code) -> Model -> 두 판단의 관계 분석

두 평가의 차이는 단순히 샘플을 두 개 입력한다는 데 있지 않습니다.

Pairwise Evaluation에서는 서로 관련된 두 코드에 대한 모델의 판단을 함께 분석함으로써 패치라는 의미 있는 코드 변화에 모델이 일관되게 반응하는지를 확인할 수 있습니다.

## 07. Experimental Analysis

**기존 AI 기반 취약점 탐지 방법 비교**

다양한 AI 기반 취약점 탐지 방법을 동일한 Vulnerable–Patched Pair 환경에서 직접 비교/분석했습니다.

기존 방법들이 일반적인 분류 환경에서 보이는 성능과 Pairwise 환경에서 나타나는 예측 행동을 함께 비교함으로써, 높은 분류 성능이 실제 취약 코드와 패치 코드의 구별 능력으로 이어지는지를 확인했습니다.

분석에서는 단순한 전체 정확도뿐만 아니라 각 Pair에서 나타나는 P-C, P-V, P-B, P-R의 분포를 확인했습니다.

이를 통해 모델이 어떤 Pair에서는 올바르게 판단하지만 다른 Pair에서는 동일한 예측을 반복하거나, 오히려 반대 방향으로 판단하는 현상을 구체적으로 분석했습니다.

---

## 08. Experimental Results

**높은 분류 성능과 Pairwise 구별 능력 사이의 차이**

실험 결과, 기존 방법들은 개별 샘플에 대한 일반적인 분류 성능과 달리 동일 함수의 취약 버전과 패치 버전을 동시에 정확하게 구별하는 데 상당한 한계를 보였습니다.

많은 경우 취약점과 관련된 코드가 수정되었음에도 취약 코드와 패치 코드에 동일한 예측을 내리는 P-V 또는 P-B가 나타났습니다.

일부 Pair에서는 취약 코드를 정상으로 판단하면서 패치된 코드를 오히려 취약하다고 판단하는 P-R(Reversed Prediction)도 확인했습니다.

특히 이러한 결과는 모델이 개별 샘플에서는 정답을 맞히더라도, 해당 판단이 실제 취약점과 관련된 코드 차이를 식별한 결과인지 별도로 검증할 필요가 있음을 보여줍니다.

### Key Insight

**High Classification Performance != Reliable Vulnerability Discrimination**

높은 분류 성능만으로는 모델이 실제 취약점과 관련된 미세한 코드 변화를 정확하게 구별한다고 단정하기 어렵습니다.

이는 모델이 판단 과정에서 취약점의 존재 여부를 결정하는 코드 변화뿐만 아니라 데이터에 존재하는 다른 특징을 활용하고 있을 가능성을 보여줍니다.

따라서 AI 기반 취약점 탐지 모델을 평가할 때에는 최종적인 예측 정확도뿐만 아니라 판단에 중요한 코드 변화에 대한 모델의 반응을 함께 분석할 필요가 있습니다.

## 09. What Did We Find?

**AI 모델의 판단 능력을 어떻게 평가해야 하는가?**

본 연구를 통해 확인한 핵심은 기존 취약점 탐지 모델의 성능이 낮다는 것 자체가 아닙니다.

더 중요한 점은 기존 평가 지표에서 나타나는 높은 성능과 모델이 실제 판단에 필요한 코드 차이를 구별하는 능력이 반드시 일치하지 않을 수 있다는 것입니다.

취약 코드와 패치 코드는 대부분의 구조와 기능이 동일합니다. 하지만 취약점과 관련된 일부 코드의 변화로 인해 보안 관점에서는 서로 다른 의미를 갖습니다.

따라서 모델이 두 코드를 정확하게 판단하기 위해서는 단순한 코드의 전체적인 유사성만으로는 충분하지 않으며, 판단에 중요한 변화에 적절하게 반응해야 합니다.

Pairwise 환경에서 기존 방법들을 분석한 결과, 모델이 취약 코드와 패치 코드에 동일한 판단을 내리거나 판단 방향이 역전되는 사례를 확인했습니다.

이는 AI 모델의 성능을 평가할 때 다음과 같은 질문이 함께 고려되어야 함을 보여줍니다.

- 모델이 정답을 맞혔는가?
- 모델은 판단에 중요한 변화가 발생했을 때 올바르게 판단을 변경하는가?

를 함께 검증해야 합니다.

## 10. Implications for Reliable AI

**정확한 AI를 넘어 신뢰할 수 있는 AI로**

본 연구의 문제의식은 소프트웨어 취약점 탐지에서 출발했지만, 보다 넓게는 AI 기반 분석 시스템의 신뢰성을 어떻게 평가할 것인가라는 문제와 연결됩니다.

AI 모델이 실제 환경에서 활용되기 위해서는 단순히 평균적으로 높은 정확도를 보이는 것만으로는 충분하지 않습니다. 입력에서 판단에 중요한 요소가 변화했을 때 모델이 해당 변화를 식별하고 예측을 적절하게 변경할 수 있어야 합니다.

특히 보안, 산업 시스템, 인프라 운영과 같이 잘못된 판단의 영향이 큰 환경에서는 모델의 최종 예측뿐만 아니라 어떤 변화에 반응하여 판단이 달라졌는지를 검증하는 것이 중요합니다.

본 연구에서 활용한 Vulnerable–Patched Pair는 이러한 관점을 실험적으로 분석할 수 있는 하나의 방법입니다. 대부분의 요소는 유지하면서 판단에 중요한 일부 요소만 변화한 Pair를 함께 평가함으로써 모델이 실제 판단에 필요한 변화에 반응하는지를 확인할 수 있습니다.

이는 AI 모델의 성능 평가가 단순한 정확도 중심에서 다음과 같은 관점으로 확장될 필요가 있음을 시사합니다.

- **Correctness** - 모델의 최종 예측이 정확한가?
- **Sensitivity** - 판단에 중요한 변화에 적절하게 반응하는가?
- **Consistency** - 유사한 조건에서 논리적으로 일관된 판단을 내리는가?
- **Reliability** - 모델의 예측을 실제 분석 과정에서 신뢰할 수 있는가?

따라서 향후 AI 기반 분석 기술에서는 높은 성능을 달성하는 것뿐만 아니라, 모델이 무엇을 근거로 판단하고 어떤 변화에 반응하는지 검증할 수 있는 평가 방법이 함께 발전해야 합니다.

## 11. Research Contribution

본 연구의 주요 기여는 다음과 같습니다.

- 기존 AI 기반 취약점 탐지 방법의 미세한 코드 차이 식별 능력에 대한 실증 분석
- 동일 함수의 Vulnerable–Patched Pair를 활용한 기존 취약점 탐지 방법 비교
- P-C / P-V / P-B / P-R 기반 모델 예측 행동 분석
- Vulnerability Pairwise Score(VPS)를 활용한 Pairwise 성능 비교
- 일반적인 분류 성능과 Vulnerable–Patched 구별 능력 사이의 차이 분석
- 기존 모델이 취약점과 관련된 코드 변화에 충분히 반응하지 못하는 사례 분석
- 정확도 중심 평가를 넘어 모델의 예측 일관성과 신뢰성을 함께 검증할 필요성 제시

## 12. Conclusion

본 연구는 기존 AI 기반 소프트웨어 취약점 탐지 모델이 높은 분류 성능을 보이는 상황에서도 실제 취약점과 관련된 미세한 코드 차이를 정확하게 구별할 수 있는지를 실증적으로 분석했습니다.

이를 위해 동일 함수의 취약 버전과 패치 버전을 하나의 Pair로 구성하고, 모델의 예측을 P-C, P-V, P-B, P-R의 네 가지 유형으로 구분하여 분석했습니다. 또한 VPS를 활용해 기존 개별 샘플 기반 평가에서는 충분히 드러나지 않는 모델의 Vulnerable–Patched 구별 능력을 비교했습니다.

실험 결과, 기존 방법들은 취약점과 관련된 코드가 변경되었음에도 동일한 판단을 유지하거나, 일부에서는 취약 코드와 패치 코드에 대한 판단이 역전되는 모습을 보였습니다. 이러한 결과는 높은 분류 성능만으로 모델이 실제 판단에 필요한 코드 차이를 식별하고 있다고 단정하기 어렵다는 점을 보여줍니다.

따라서 AI 기반 취약점 탐지 기술을 실제 보안 분석에 활용하기 위해서는 단순한 분류 정확도를 넘어, 판단에 중요한 코드 변화에 모델이 올바르게 반응하는지 함께 검증할 필요가 있습니다.

본 연구는 이러한 관점에서 Vulnerable–Patched Pair 기반 평가를 통해 기존 AI 기반 취약점 탐지 방법의 한계를 실증적으로 분석하고, 향후 보다 신뢰할 수 있는 AI 기반 소프트웨어 분석 기술을 위한 평가 방향을 제시합니다.
